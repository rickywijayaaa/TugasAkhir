## Topik: Peningkatan Evaluasi RAG via Hybrid Retrieval

## Context

Tugas akhir saat ini mengevaluasi mitigasi halusinasi RAG-LLM dengan **hanya BM25** sebagai retriever pada 6 konfigurasi (Baseline/QR/CR × Llama 3.2/GPT-4.1-mini). Konfigurasi terbaik saat ini adalah **CR + GPT-4.1-mini** dengan 68,4% label accuracy.

Paper referensi ([Zhang & Zhang, 2025](https://www.mdpi.com/2227-7390/13/5/856)) mengategorikan sumber halusinasi RAG menjadi 4 masalah di fase retrieval: **data source, query, retriever, retrieval strategy**. Penelitian saat ini sudah menyentuh query (QR) dan retrieval strategy (CR) tapi **belum menyentuh masalah retriever itu sendiri** (BM25 sebagai satu-satunya sumber kandidat).

Literatur biomedis RAG terkini ([arxiv 2505.01146](https://arxiv.org/pdf/2505.01146), [Premai Blog](https://blog.premai.io/hybrid-search-for-rag-bm25-splade-and-vector-search-combined/)) menunjukkan bahwa **hybrid retrieval (BM25 + dense)** secara konsisten mengungguli sparse atau dense tunggal karena:
- BM25 unggul untuk exact entity matching (istilah medis, nama obat)
- Dense retrieval menangkap kesamaan semantik (sinonim, parafrasa)
- Fusion via RRF (Reciprocal Rank Fusion) menggabungkan kekuatan keduanya

Tujuan perubahan: **memperkuat story thesis dengan ablation study retriever** (BM25 vs Dense vs Hybrid) yang menjawab masalah ke-3 dari paper Zhang, bukan sekadar naikkan akurasi.

## Perbedaan Utama vs Notebook Sebelumnya

### Notebook 02, 03, 04, 05 (sebelumnya): Hanya **1 Retriever**

```
Query -> BM25 (sparse/keyword matching) -> top-K dokumen -> LLM
```

BM25 bekerja dengan **kata kunci persis** (exact matching):
- "aspirin" di query hanya akan match dengan "aspirin" di dokumen
- Tidak menangkap sinonim ("acetylsalicylic acid")
- Tidak menangkap parafrasa ("drug for blood thinning")

### Notebook 06 (Hybrid): **2 Retriever Digabung**

```
                 +--> BM25 top-50 (sparse/keyword)  --+
Query ---------- |                                     | --> RRF Fusion -> top-5 -> LLM
                 +--> Dense top-50 (semantic)       --+
```

Dua retriever berjalan **paralel**, lalu hasilnya digabung.

### Perbandingan Teknis

| Aspek | Notebook Sebelumnya | Notebook 06 (Hybrid) |
|-------|---------------------|----------------------|
| **Retriever** | BM25 saja | BM25 + Dense |
| **Cara Match** | Kata kunci persis | Kata kunci + makna semantik |
| **Index** | `pubmedqa_bm25.pkl` | `pubmedqa_bm25.pkl` + `pubmedqa_chroma/` |

| **Cost Embedding** | $0 | ~$0,03 (sekali) + $0,001 per query |
| **Top-K** | top-5 langsung | top-50 × 2 -> RRF -> top-5 |

## Cara Kerja Langkah per Langkah

### Contoh Query
```
"Does aspirin reduce the risk of myocardial infarction?"
```

### Langkah 1: BM25 Retrieval (Sparse/Keyword)

BM25 tokenize query lalu cari dokumen yang kata kuncinya paling banyak cocok.

```python
tokens = ['does', 'aspirin', 'reduce', 'risk', 'myocardial', 'infarction']
# BM25 scan 1706 dokumen, hitung skor per dokumen
# Skor tinggi = banyak term query muncul di dokumen
```

**Kelebihan:** Bagus untuk istilah medis **exact** (nama obat, singkatan, angka dosis)
**Kelemahan:** Miss dokumen yang pakai parafrasa

Output BM25:
```
[doc_142: 45.2, doc_891: 38.7, doc_23: 32.1, ..., 50 dokumen]
```

### Langkah 2: Dense Retrieval (Semantic)

Query di-embed jadi vektor 1536-dimensi oleh OpenAI, lalu cari dokumen yang vektornya paling mirip (cosine similarity).

```python
query_vector = openai_embed("Does aspirin reduce...")  # [0.12, -0.34, ..., 0.78]
# Hitung cosine similarity dengan 1706 doc vectors yang sudah di-embed
# Skor tinggi = makna dokumen mirip dengan query
```

**Kelebihan:** Nangkep **makna** (aspirin ≈ acetylsalicylic acid, MI ≈ heart attack)
**Kelemahan:** Bisa miss exact match untuk nomor/kode spesifik

Output Dense:
```
[doc_891: 0.85, doc_456: 0.82, doc_142: 0.79, ..., 50 dokumen]
```

### Langkah 3: Reciprocal Rank Fusion (RRF)

RRF menggabungkan dua ranking tanpa butuh normalisasi skor. Formula sederhana:

```
RRF(d) = sum_r [ 1 / (k + rank_r(d)) ]
```

Dengan `k=60` (standar literatur).

**Contoh perhitungan untuk doc_142:**
- Di BM25: rank ke-1 (paling relevan) -> skor RRF: `1/(60+1) = 0.0164`
- Di Dense: rank ke-3 -> skor RRF: `1/(60+3) = 0.0159`
- Total RRF = `0.0164 + 0.0159 = 0.0323`

**Contoh untuk doc_891:**
- Di BM25: rank ke-2 -> `1/(60+2) = 0.0161`
- Di Dense: rank ke-1 -> `1/(60+1) = 0.0164`
- Total RRF = `0.0325`

**Contoh untuk doc_999 (hanya muncul di dense):**
- Di BM25: tidak muncul (skor 0)
- Di Dense: rank ke-5 -> `1/(60+5) = 0.0154`
- Total RRF = `0.0154`

Dokumen yang muncul **di kedua retriever** otomatis dapat skor lebih tinggi. Ini yang bikin hybrid lebih robust.

### Langkah 4: Ambil Top-5 Hasil RRF

```python
top_5 = [
    RetrievalResult(doc_891, rrf=0.0325, bm25=38.7, dense=0.85),
    RetrievalResult(doc_142, rrf=0.0323, bm25=45.2, dense=0.79),
    RetrievalResult(doc_456, rrf=0.0302, bm25=25.4, dense=0.82),
    RetrievalResult(doc_23,  rrf=0.0291, bm25=32.1, dense=0.71),
    RetrievalResult(doc_777, rrf=0.0287, bm25=18.2, dense=0.80),
]
```

Perhatikan: doc_891 dan doc_456 tidak ada di top BM25 dengan skor tinggi (bisa jadi pakai parafrasa), tapi Dense nemu. Doc_142 sebaliknya, BM25 paling kuat tapi Dense juga nemu di top-3. Keduanya masuk final.

### Langkah 5: LLM Generate Jawaban (sama seperti notebook lain)

```python
context = concat(top_5_docs)
answer = openai_generate(prompt.format(context=context, question=original_query))
label = extract_label(answer)  # yes / no / maybe
```

## Kenapa Hybrid Lebih Bagus?

### Skenario 1: Query pakai parafrasa

**Query:** "Can heart attacks be prevented with blood thinners?"
- BM25 score rendah (kata "aspirin" tidak ada di query, tapi ada di dokumen target)
- Dense score tinggi (makna "blood thinner" mirip "aspirin")
- **Hybrid: dapat dokumen relevan lewat Dense**

### Skenario 2: Query pakai kode/angka spesifik

**Query:** "Effectiveness of 75mg aspirin"
- BM25 score tinggi (exact match "75mg", "aspirin")
- Dense score bisa agak rendah (angka tidak well-represented di embedding)
- **Hybrid: dapat dokumen relevan lewat BM25**

### Skenario 3: Konsensus kedua retriever

**Query:** "Does aspirin prevent myocardial infarction?"
- Dokumen A punya kata "aspirin" + "myocardial infarction" -> BM25 tinggi
- Dokumen A juga semantik relevan -> Dense tinggi
- **RRF: dokumen A di top karena muncul di kedua list (konsensus)**

   ```python
       scores = {}
       for rank_list in rank_lists:
           for rank, doc_id in enumerate(rank_list):
               scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank + 1)
       return sorted(scores.items(), key=lambda x: -x[1])
   ```

## Hipotesis yang Diuji (untuk story thesis)

1. **H1:** Dense retrieval alone akan kalah dari BM25 pada istilah medis spesifik (exact entity matching).
2. **H2:** Hybrid (BM25 + Dense via RRF) akan mengungguli BM25 dan Dense masing-masing karena menutupi kelemahan satu sama lain.
3. **H3:** Hybrid + CR akan menjadi konfigurasi terbaik secara keseluruhan, mengungguli CR OpenAI saat ini (68,4%).
4. **H4:** Peningkatan lebih besar pada label `no` dan `maybe` (yang sebelumnya rendah) karena dense bisa menangkap negasi dan nuansa semantik.

Jika hipotesis terbukti, thesis punya kontribusi baru: "Hybrid retrieval menyelesaikan salah satu masalah fundamental retriever yang diidentifikasi [Zhang & Zhang, 2025] untuk domain biomedis".

## Output yang Diharapkan

Kalau hipotesis benar, Hybrid akan:
1. **Naikkan accuracy label `no`** — karena Dense nangkep negasi lebih baik
2. **Naikkan accuracy label `maybe`** — konteks semantik lebih relevan untuk kasus ambigu
3. **Faithfulness ≈ 0,90** — kualitas konteks lebih baik -> LLM lebih grounded
4. **Context Recall lebih tinggi** — karena dapat dokumen dari 2 sumber, cakupan lebih luas
